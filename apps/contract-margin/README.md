# Solvren AI Contract Margin Control

This isolated Next.js/Supabase application supports a contract-margin audit and decision workflow: verified organization accounts, MFA-protected Finance and Engineer roles, versioned contracts, metadata-only AI cost and outcome imports, customer mapping, OpenAI and Anthropic organization cost connections, optional read-only Stripe revenue evidence, supplier reconciliation, a ranked portfolio, immutable quote decisions, 14/30-day contract run-rate forecasts, owned margin issues, email alerts, weekly executive digests, and frozen PDF/CSV month-end reports. It does not share data or credentials with the legacy Solvren application.

## Local development

Use Node.js 22 or newer, pnpm, Docker, and the Supabase CLI. Copy `.env.example` to `.env.local`, run `supabase start`, set the local URL/publishable/service-role keys from its output, then run `pnpm install` and `pnpm dev`. Set `APP_ORIGIN=http://localhost:3000`. Local invitation email is available in Supabase Inbucket; production invitations require `RESEND_API_KEY` and `INVITE_FROM_EMAIL` on a verified domain. A local worker call requires a random `CRON_SECRET` of at least 32 characters and `Authorization: Bearer <CRON_SECRET>` at `/api/internal/import-worker`.

The ordered SQL migrations create the application schema, policies, private Storage buckets, Vault-backed connection secrets, and `pgmq` import and connector queues. Do not run them against the legacy database.

## Production configuration

1. Create a dedicated Supabase project with Postgres 17 and apply every migration in `supabase/migrations` in order. Confirm `btree_gist`, `pgmq`, Vault, Auth, and Storage are available. Keep backups and exercise a database-plus-Storage restore before enrolling customers.
2. Set Supabase Auth's site URL and exact callback allowlist for `https://<app-domain>/auth/callback`. Configure production SMTP, Google and Azure OAuth, verified-email enforcement, TOTP, and the password/session settings described in `supabase/config.toml`. Azure must return an email claim. Session time-box controls require a Supabase plan that supports them.
3. Deploy this app over HTTPS with all variables in `.env.example`. `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are browser-visible. `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, and Resend credentials must stay server-side. Use a fresh high-entropy `CRON_SECRET` of at least 32 characters. Restrict access to production environment variables and separate the production and preview Supabase projects.
4. Deploy `vercel.json` with the application root set to `apps/contract-margin`. The import, margin monitor, and margin delivery workers run every minute; the connector worker runs every five minutes and the retention worker every fifteen minutes. These schedules require a Vercel plan that supports minute-level cron. Keep each worker's deployment runtime at or above its configured 60-second maximum. All workers require `Authorization: Bearer <CRON_SECRET>`. Set `ALERT_FROM_EMAIL` to a sender on a verified Resend domain. Monitor failed jobs, stale connections, retention failures, alert delivery failures, and worker HTTP failures. Review Auth, Storage, database, and worker logs without recording prompts, responses, ingestion keys, or connector secrets.
5. Invite an Owner, Finance, and Engineer. Enroll TOTP for privileged users. In **Data & imports**, Finance sets the default margin target and imports contracts and supplier statements; Engineer imports usage/outcomes/direct costs, configures mappings and rate cards, or connects a Langfuse v4 project. In **Reconcile & reports**, Engineer or Owner connects OpenAI/Anthropic organization-admin cost credentials, and Finance or Owner may connect a Stripe restricted read-only key. Review connection health and supplier variance, resolve source IDs, confirm contract terms, then freeze a closed reporting period. Open the portfolio and customer reports to verify the first 30-day result. In **Quote decisions**, Finance or Owner compares and saves proposed terms. In **Margin issues**, assign and resolve conditions, set alert thresholds and quiet hours, and confirm email delivery and weekly digests from a verified mailbox.

## Ingestion contract

Each CSV template is downloadable in **Data & imports**. A CSV contains 1–10,000 rows and is at most 4 MB. Contract and statement files are atomic: invalid rows reject the entire file. Event files queue valid rows and record invalid row numbers with downloadable reasons. The source ID is a stable namespace such as `application` or `billing_export`; source event IDs must remain stable across retries. Replaying an event does not add it twice. Unknown model costs remain unpriced, and unmapped events remain visible outside customer totals. The portfolio shows known contribution as an upper bound whenever costs are incomplete.

Engineers can create an MFA-protected ingestion key and send up to 500 metadata-only rows and 1 MB per request to `POST /api/ingest/events`. The JSON object contains `kind` (`usage`, `outcomes`, or `direct_costs`), `source`, and `rows`. Use the corresponding CSV template's camelCase field names in each JSON row. Include `Authorization: Bearer <key>` and `Content-Type: application/json`. A successful response is `202` with a job ID; inspect the job in **Data & imports**. An invalid batch returns `422` and queues no rows. Keys are shown once, can be revoked, are limited to 60 requests per minute each, and are automatically revoked when their creator leaves or loses an eligible role.

Langfuse connections are scoped to one provider and region. Solvren fetches Langfuse v2 observation fields for IDs, model, usage, cost, and trace context, without requesting prompt or response bodies. Backfills are checkpointed and resumable. Langfuse reported cost is used when present; otherwise effective-dated model rates calculate a cost from token buckets. Direct supplier statements are period-specific and non-overlapping. The report distinguishes observed cost from statement coverage and does not infer that missing cost is zero.

## Reconciliation and lifecycle

OpenAI and Anthropic connections fetch daily organization costs by project or workspace and line item. Initial backfill covers 30 completed UTC days. Scheduled refresh replays the last three completed days; manual Sync now can requeue failed days. A disconnected credential is removed from Vault and stops new syncs. Reconciliation does not allocate the difference between supplier totals and customer-attributed direct usage. Missing scope IDs, unmapped events, unpriced events, incomplete day coverage, stale credentials, and supplier variance remain visible. Anthropic Priority Tier and cloud-reseller billing are outside the Anthropic Admin Cost API and require supplied statements.

Stripe access uses only a restricted key and GET requests for customers, subscriptions, and recent invoices. Subscription list price is a draft suggestion; Finance confirms the signed USD contract value and effective date before saving. Metered, mixed, and non-USD subscription terms require manual review. Invoice discounts and credit notes are displayed separately; non-USD invoices are flagged without presenting a false USD conversion. Stripe never changes billing objects or contract terms automatically.

A frozen report stores its full evidence snapshot and version in Postgres, plus a PDF and CSV in a private bucket. Reports are immutable after freezing; downloads require organization access and issue a signed link valid for 24 hours. The customer source export is available in **Reconcile & reports**, one dataset at a time, with an `X-Next-Cursor` response header for large datasets. Normalized events and supplier cost buckets are pruned after 13 months. An Owner can request organization closure with a fresh authenticator code; access and credentials are removed immediately, with database and private Storage purged by the retention worker after 29 days.

## Quote decisions and margin operations

The quote console supports up to three side-by-side monthly scenarios, each with a workflow mix, expected completed outcomes, base fee, discount, allowance, overage, target margin, and adverse volume stress. Median and p90 direct unit costs come from the latest 60 completed UTC days. A workflow with fewer than 30 priced completed runs requires explicit manual median and adverse unit-cost assumptions; the saved decision labels that basis and freezes its input, source sample, formula version, output, owner, decision, and notes. Revisions create immutable versions. Suggestions show price and allowance arithmetic, but never change billing, routing, or access automatically.

Customer pages show trailing 14- and 30-day cost run rates and a period-end margin estimate under the effective contract. Forecasts disclose active-day coverage, completed-outcome volume, and unknown-cost gaps; sparse or unpriced evidence is marked low confidence and does not trigger a projected breach alert. The margin monitor records observed floor breaches, sufficiently supported projected breaches, daily cost spikes, stale supplier connections, and material reconciliation gaps. Each condition has one durable issue per customer or provider, an owner, evidence, and an audit trail for acknowledge, comment, assign, snooze, and resolve actions. Unresolved issues remain visible after a signal clears. A recurring signal after resolution opens a new occurrence and alert.

Finance or Owner can configure materiality thresholds, timezone, quiet hours, and weekly digest timing. Alert emails are queued transactionally, deduplicated by issue event and recipient, retried with a stable provider idempotency key, deferred during quiet hours, and skipped when the issue is resolved or the recipient loses access. The weekly digest includes newly at-risk and resolved issue counts, current known exposure and change from a prior sent digest, data-confidence gaps, and links to evidence. These are known-cost estimates, not booked revenue or claimed savings. Delivery failures and recent error messages are visible in **Margin issues**; Finance or Owner can return failed alerts and digests to the queue after fixing the mail service. Scan failures remain visible for operational review.

## Verification and release gate

Run `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `pnpm build`. Automated local tests cover imports, provider response normalization, Stripe revenue evidence, CSV safety, real PDF generation, quote economics, sparse-evidence rules, run-rate confidence, and alert gating. The SQL migrations were executed against a disposable PostgreSQL 17 database with representative contract amendments, mapping/rate recalculation, retry deduplication, cross-tenant denial, key revocation, connector day replay, variance, frozen-report immutability, retention, account closure, quote immutability, issue audit/deduplication, queue retries, and digest totals. That database used stand-ins for Supabase services; it does **not** certify a deployed Supabase environment.

Before admitting production users, run the following against the actual dedicated Supabase project and deployment: sign-up/email verification and Google/Azure login; invitation and TOTP role changes; direct cross-tenant SQL/API denial; Storage upload/download/cleanup and 24-hour signed-link expiry; Vault connection/revocation; `pgmq` retries and worker cron authorization; genuine OpenAI, Anthropic, Stripe, and Langfuse source pages; API and CSV imports with invalid and duplicate rows; provider-statement overlap rejection; quote approval/revision with both 30-run and sparse workflows; monitor detection, deduplication, snooze expiry, and recurrence; alert and digest delivery from the verified Resend domain through quiet hours and retries; report freeze/versioning against genuine 30-day source files; cancellation purge; and backup/restore. Resolve failures before release. A build with placeholder public keys only proves compilation.

The local 500-customer, two-million-usage-event fixture completed a direct bulk database insert in about two minutes. Single-call portfolio and reconciliation SQL each took roughly 4–6 seconds on the disposable local database, so the 5-second p95 page target is **not yet verified**. Measure full page latency, sustained ingestion, and concurrent queries on the production-sized Supabase tier before committing to that target.
