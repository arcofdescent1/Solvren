## Product Areas

### Home

The first screen after login. Home summarizes money at risk, items needing action, problems detected, value protected, and setup health.

### Decisions

The prioritized list of work that needs a person to decide, approve, add proof, or follow up.

### Problems

Revenue-impacting issues Solvren found across connected systems.

### Proof

The value story: protected revenue, avoided loss, outcomes, value stories, reports, and proof packets.

### Setup

Connected systems, users, rules, security, license, and organization settings.

---

## Operational Concepts

### Decision

A piece of work that needs approval, proof, ownership, or follow-up. Decisions can include change reviews, assigned problems, blocked work, overdue items, and system tasks.

### Problem

A detected issue that may be costing money, blocking customers, or putting revenue workflows at risk.

### Proof

Evidence that a decision is safe, a problem was handled, or value was protected. Proof can include evidence links, approval history, delivery logs, outcome records, value stories, and proof packets.

### Connected System

A system Solvren watches or works with, such as billing, CRM, finance, support, code, data warehouse, or ticketing systems.

### Profile

Each user can set a display name and profile picture. Avatars appear in the topbar, team management, decisions, and approval ownership areas.

## Technical Concepts

These terms appear in admin, architecture, details, and audit views.

### Signal

A raw event from an integrated system.

### Detector

Logic that identifies patterns or anomalies.

### Issue

The technical record behind a Problem.

### Impact

Estimated financial effect of a problem or decision.

### Playbook

A defined set of actions to resolve a problem.

### Execution

The process of applying a playbook.

### Verification

Confirmation that a problem has been resolved or a value claim has supporting evidence.

### Value

Measured outcome, including recovered revenue or avoided loss.

### Restricted Access

Restricted records are visible only to permitted owners, admins, creators, assigned approvers, or explicitly granted users.

### Safe Automation

Controlled execution using policies, approvals, simulations, and confidence thresholds.
